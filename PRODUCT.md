# Archetype Product Context

register: product

## Product Purpose

Archetype is a Design Architecture Compiler. It converts product context, goals, visual evidence, brand material, and optional implementation evidence into a Product Experience Blueprint, Design System Package, Frontend Agent Contract, and validation/readiness reports.

## Primary Users

- Founder or solo builder who needs a buildable product UI architecture.
- Product designer who needs system-level UX and design-system architecture.
- Frontend engineer who needs precise implementation contracts.
- Frontend agent or coding agent that must build UI without inventing design decisions.
- Agency or product studio preparing client-ready UX architecture.
- Design system team auditing and governing product UI.

## Product Principles

- Evidence before decisions.
- Product architecture before screen design.
- Workflows before components.
- Product-specific patterns before generic UI kits.
- Accessibility as an architectural constraint.
- Traceability for every major decision.
- No frontend-agent improvisation when a required decision is missing.

## Tone

Calm, precise, direct, technical, and low-hype. The product should feel like a senior architecture tool: confident, inspectable, and careful with unknowns.

## Anti-References

- Generic SaaS landing pages.
- Decorative dashboards.
- Overly theatrical AI interfaces.
- UI-kit galleries disconnected from product workflows.
- Pretty screens without build contracts.

## Workbench Goal

The workbench should help users inspect generated packages, understand readiness, review evidence and decisions, inspect architecture traces, and validate frontend-agent buildability.
